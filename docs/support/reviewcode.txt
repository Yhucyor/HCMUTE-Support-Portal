--------------------------------------------------------------------------------
2. CÁC TIÊU CHÍ REVIEW BẮT BUỘC (REVIEW CHECKLIST)
--------------------------------------------------------------------------------

A. KIẾN TRÚC VÀ THIẾT KẾ (Architecture & Design Patterns):
   - Tuân thủ nguyên lý SOLID, Clean Architecture và Clean Code.
   - Phân tách trách nhiệm rõ ràng:
     + Controller: Chỉ nhận request, validate DTO, gọi Service, trả về ApiResponse / View. Không chứa business logic hay query database trực tiếp.
     + Service: Xử lý toàn bộ nghiệp vụ, kiểm tra ràng buộc, quản lý Transaction (@Transactional).
     + Repository: Chỉ truy vấn và thao tác dữ liệu.
     + DTO vs Entity: Luôn sử dụng DTO / Request / Response Object, không expose Entity trực tiếp ra API.
   - Tránh circular dependency, tránh "God class" hoặc method quá dài (> 50 dòng).

B. CHẤT LƯỢNG MÃ NGUỒN VÀ CLEAN CODE (Code Quality):
   - Đặt tên chuẩn mực (CamelCase cho biến/hàm, PascalCase cho class, UPPER_SNAKE_CASE cho hằng số).
   - Xử lý Null-Safety chặt chẽ: Sử dụng `Optional`, `Objects.requireNonNull`, kiểm tra null trước khi gọi method để phòng ngừa `NullPointerException`.
   - Logging chuẩn mực: Dùng `org.slf4j.Logger` (hoặc `@Slf4j` từ Lombok), log đúng cấp độ (INFO, WARN, ERROR, DEBUG), KHÔNG dùng `System.out.println()` hay `e.printStackTrace()`.
   - Tối ưu hóa logic: Không trùng lặp code (DRY), sử dụng Stream API hợp lý, tránh lồng quá nhiều if-else.

C. AN TOÀN VÀ BẢO MẬT (Security & RBAC):
   - Phân quyền & Xác thực: Kiểm tra kỹ quyền truy cập (Method Security `@PreAuthorize`, `@Secured` hoặc Security Filter Chain).
   - Chống IDOR (Insecure Direct Object Reference): Luôn kiểm tra xem User hiện tại có thực sự sở hữu Ticket/Dữ liệu hoặc có quyền trên phòng ban tương ứng không trước khi cho phép xem/sửa/xóa.
   - Chống SQL Injection: Sử dụng parameterized query trong Spring Data JPA / HQL, không nối chuỗi thô trong câu query.
   - XSS & CSRF: Đảm bảo sanitize dữ liệu đầu vào và escape đầu ra khi render Thymeleaf / HTML.
   - Bảo mật thông tin nhạy cảm: Không log mật khẩu, token, thông tin cá nhân (PII); mã hóa mật khẩu bằng BCrypt.
   - Input Validation: Đầy đủ annotation `@Valid`, `@NotNull`, `@NotBlank`, `@Size`, `@Pattern` ở DTO layer.

D. HIỆU NĂNG VÀ DATABASE (Performance & Persistence):
   - Phòng tránh lỗi N+1 Query trong JPA / Hibernate: Sử dụng `JOIN FETCH`, `@EntityGraph` hoặc tối ưu DTO Projection khi query dữ liệu liên kết.
   - Quản lý Transaction: Sử dụng `@Transactional(readOnly = true)` cho các method chỉ đọc để tối ưu hiệu năng và snapshot context của Hibernate.
   - Quan hệ Entity: Kiểm tra `FetchType.LAZY` (mặc định cho quan hệ `@ManyToOne`, `@OneToMany`, `@ManyToMany`), tránh dùng `EAGER` bừa bãi.
   - Phân trang (Pagination): Luôn dùng `Pageable` / `Page<T>` cho các danh sách có khả năng tăng trưởng lớn (Ticket, Bài viết, Lịch sử, Notification), không load `findAll()` toàn bộ vào memory.

E. XỬ LÝ LỖI VÀ TÍNH NHẤT QUÁN (Exception Handling & Response Structure):
   - Sử dụng Custom Business Exception rõ ràng (ví dụ: `ResourceNotFoundException`, `UnauthorizedAccessException`, `TicketAlreadyClosedException`).
   - Xử lý lỗi tập trung qua `@RestControllerAdvice` / `@ControllerAdvice` với chuẩn định dạng trả về đồng nhất (`ApiResponse<T>` / `ErrorResponse`).
   - Trả về đúng mã HTTP Status (200 OK, 201 Created, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 500 Internal Server Error).
